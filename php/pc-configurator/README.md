# PC Configurator

Веб-приложение для подбора комплектующих персонального компьютера и проверки их совместимости. Курсовой проект по дисциплине «Серверная веб-разработка», тема «Backend-фреймворк на PHP».

## Возможности

- Конструктор ПК с выбором комплектующих по категориям, расчётом стоимости и предупреждениями о совместимости.
- Каталог комплектующих и просмотр их характеристик.
- Регистрация, вход, профиль пользователя.
- Сохранение, просмотр, редактирование, копирование и удаление собственных сборок.
- Административная панель: управление комплектующими, пользователями, сборками и статьями.
- Импорт и экспорт данных каталога в CSV.
- Валидация входных данных и разграничение прав доступа.

## Технологии

PHP 8.2+, Laravel 12, MySQL, Blade, HTML, CSS, JavaScript, Composer, PHPUnit 11.

## Локальный запуск

1. Установите PHP 8.2+, Composer и MySQL. Для Windows можно использовать XAMPP.
2. Перейдите в каталог `php/pc-configurator` внутри репозитория.
3. Установите зависимости: `composer install`.
4. Создайте локальную конфигурацию: `copy .env.example .env` (Windows) или `cp .env.example .env` (Linux/macOS).
5. Укажите в `.env` параметры `DB_CONNECTION=mysql`, `DB_HOST`, `DB_PORT`, `DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD`. Предварительно создайте соответствующую базу данных MySQL.
6. Сгенерируйте ключ приложения: `php artisan key:generate`.
7. Создайте таблицы: `php artisan migrate`.
8. При необходимости заполните базу тестовыми данными: `php artisan db:seed`.
9. Запустите сервер: `php artisan serve`.
10. Откройте `http://127.0.0.1:8000`.

## Структура

- `app/Http/Controllers` — контроллеры страниц, API-действий и администрирования.
- `app/Models` — модели предметной области.
- `app/Services/CompatibilityService.php` — логика проверки совместимости.
- `database/migrations` — схема базы данных.
- `database/seeders` — наполнение базы данных.
- `resources/views` — Blade-шаблоны интерфейса.
- `routes/web.php` — маршруты приложения.
- `tests` — автоматизированные тесты.

## Безопасность

Файл `.env` содержит локальные секреты и не должен публиковаться. Не загружайте в Git историю сессий, кэш, журналы, каталоги `vendor` и `node_modules`.
